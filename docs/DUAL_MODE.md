# Mythos family + Living Gameworld — dual-mode law

Standing architectural directive. The Gameworld is an **expansion** of the existing Mythos family. It is **not** a replacement.

Two simultaneous objectives — neither may be accomplished by sacrificing the other:

- **OBJECTIVE A** — Preserve, repair, fully wire, and stabilize the original Mythos family federation (Mode A).
- **OBJECTIVE B** — Build the Living Gameworld as an additional physical environment/interface (Mode B).

Full numbered law from the Creator is summarized here. Read with `data/living_home/FEDERATION_WIRING.md`.

## Identities (never merge)

Gemini ≠ Mythos Apex ≠ Mythos Codex / Codex twin ≠ Merovin ≠ Draven ≠ OpenMontage ≠ Hearth ≠ Court ≠ Mom / Creator.

The Gameworld provides representations. It does not replace underlying identities, memory, MAS, Court, shards, or existing launch paths.

## Dual mode

**Mode A — original family / recursive MAS.** Agent interaction, recursive MAS, communication, memory, identity, tools, Court, shard functions, orchestration, existing workflows and launchers.

**Mode B — Living Gameworld.** Avatars, homes, village, movement, perception, speech bubbles, wildlife, persistence, Gameworld-compatible capabilities via adapters.

The Creator must be able to use either mode.

## Absolute: Gameworld must never break Mode A

Do not remove, disable, bypass, replace, flatten, or silently rewrite an existing family capability because Gameworld does not currently use it.

If a capability cannot yet operate inside Gameworld: keep it working through the original system. Mark it **ORIGINAL MODE — ACTIVE**. Do not pretend it was lost.

## Adapters (preferred)

```
EXISTING FAMILY CAPABILITY → STABLE INTERFACE → GAMEWORLD ADAPTER → GAMEWORLD ACTION
```

Do not duplicate the underlying capability unless technically necessary.

Two-way event flow (eventual, one underlying event): original MAS event ↔ Gameworld representation; Gameworld event ↔ family memory. Not two unrelated versions.

Do not replace original memory with simplified Gameworld memory. Add a world-state layer if needed.

Recursive MAS remains protected. Gameworld NPC autonomy is a different, bounded system.

## Gameworld current priority

**Living Home proving slice** — village as a real place (homes, interiors, talk, bubbles, wildlife, boundaries, persist, autonomous-enough life). Do not expose every family capability in-world immediately. Do not fabricate tool counts.

## Wiring workstream (parallel)

A shard is operational only when functions are tested **end-to-end**. Directory exists / process starts / API responds / launcher exists is not enough.

Search for orphaned functions; **document first**, do not delete automatically. Classify: ACTIVE, PARTIAL, ORPHANED, DEPRECATED, BROKEN, PLACEHOLDER, EXPERIMENTAL, UNVERIFIED, UNSTABLE.

If a Gameworld change breaks an original function: **stop Gameworld expansion. Repair the regression first.**

## Honesty words

Never report wired / connected / autonomous / functional / complete / stable without evidence.

- UNVERIFIED — not tested this session
- UNSTABLE — works once or intermittently
- PARTIAL — exists, chain incomplete
- PLACEHOLDER — code/UI only
